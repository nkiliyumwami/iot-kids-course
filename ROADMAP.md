# Roadmap

One new idea per lesson. Each daily run takes the first unchecked item. See `AGENT.md` for the rules.

## Start here

- [x] **0. Pin Detective: Meet Your ESP32** (`00-meet-esp32`): no hardware yet. Missions on the 3D board teach its
  parts, the pin groups (power, ground, GPIO, special) and the Pin(25) = D25 trick, with tappable "maker words".
- [x] **Circuit Lab 1: Light It Up** (`lab1-light-it-up`): no code. Build one LED circuit on the 3D breadboard, part by part:
  the breadboard's hidden strips, the LED's long and short legs, the resistor (pretend current meter), unplug first, the
  resistor across the gap in column 7, the LED in i7/i8, black wires to the − rail and GND, the red wire from 3V3 last,
  then plug in. A fix-it shop of three broken circuits, then the same build on the real board (3V3 lights it with no code).
- [x] **Circuit Lab 2: Let Code Switch It** (`lab2-code-switch`): no new hardware. Move the red wire from 3V3 to D25;
  `Pin(25, Pin.OUT)`, `led.value(1)` / `led.value(0)`, then a blink with `while True:` and `time.sleep()`, run on the real board.

## Part 1: Build the thing

- [x] **1. My First Traffic Light** (`01-traffic-light`, ✅ tested on a real ESP32 with all wiring, 2026-10-12): outputs. ESP32 switches D25/D26/D27 to light three LEDs
  through 330 Ω resistors. `Pin(…, Pin.OUT)`, `value()`, `while True:`, `time.sleep()`.
- [x] **2. Make It Yours: Light Patterns** (`02-patterns`, ✅ tested on a real ESP32 with all wiring, 2026-10-12): no new hardware. Variables for the times, a
  `set_lights(r, y, g)` function so each phase is one line, and `print()` to see what the program is doing
  (show the Thonny console). Challenge: design your own pattern.
- [x] **3. The Pedestrian Button** (`03-pedestrian-button`, ✅ tested on a real ESP32 with all wiring, 2026-10-12): a push button on a safe input pin.
  `Pin.IN` with `Pin.PULL_UP` (why a pin "floats" without it, why pressed reads 0), and `if`. First version: while
  the button is held, the light shows red.
- [x] **4. A Fair Crossing** (`04-fair-crossing`): no new hardware. Remember a press in a variable, finish the
  green safely, then give pedestrians their turn. Why buttons "bounce" and a simple fix.
- [x] **5. Beep Beep: Crossing Sound** (`05-crossing-sound`): a buzzer that beeps while pedestrians may cross.
  `PWM`: sound is switching on and off very fast; frequency changes the pitch.
- [x] **6. Measuring Light** (`06-measuring-light`): an LDR with a 10 kΩ resistor as a voltage divider on an ADC1 pin.
  Analog vs digital, readings from 0 to 4095, printing the numbers while covering the sensor.
- [x] **7. Night Mode** (`07-night-mode`): no new hardware. A threshold turns on flashing yellow when it's dark.

## Part 2: Connect it

- [x] **8. Hello, Wi-Fi** (`08-hello-wifi`): what a network and an IP address are; `network.WLAN` to connect and print the IP.
  Keep Wi-Fi passwords out of shared code (a separate `secrets.py`).
- [x] **9. Your Traffic Light's Web Page** (`09-status-page`): a tiny web server on the ESP32 that shows the current light
  on a phone on the same Wi-Fi. Read-only.
- [x] **10. Control It From Your Phone** (`10-phone-control`): buttons on the web page send commands; the safety rules
  (never red and green together, pedestrians get their full time) still win.

## Part 1½: Sensor modules (any order, unlocked by lesson 7)

Standalone projects from a bare board: one new sensor plus one output the learner already knows (LED on D25/D26/D27 with
330 Ω, buzzer on D13, or the servo). Every module keeps lesson 7's shape: read → `if value < THRESHOLD:` → do → `else:` → undo.
Start each from `lessons/_module-template/`; look-alike parts go in its "Swap the part" box. Rules in `AGENT.md`, "Sensor modules".

- [x] **Servo Says Hello** (`m-servo`): new part: SG90 servo, signal on D18, red wire on a regulated 5 V supply with the grounds joined (VIN only for a quick test; never 3V3 or a GPIO). New code idea:
  `PWM(Pin(18), freq=50)` and `duty_u16()`, an angle as a pulse length. If-line: none (output module; it sets up
  `if … : turn(90) else: turn(0)`). Swap the part: none. 3D scene: a waving arm on the desk.
- [x] **The Parking Gate** (`m-parking-gate`, needs `m-servo`): new part: HC-SR04P distance sensor (3.3 V version), TRIG on
  D19, ECHO on D21 (a 5 V HC-SR04 needs a 1 kΩ/2 kΩ divider on ECHO). New code idea: `time_pulse_us()` and `t / 58` for
  centimetres. If-line: `if d < NEAR:` → gate(90), else gate(0). Swap the part: IR obstacle sensor on D14. Challenge: the
  same parts make a smart dustbin lid. 3D scene: the gate (the template's scene, `assets/models/modules/parking-gate.glb`).
  Library: ≈46 ultrasonic builds (parking/toll gates, barriers, dustbins).
- [x] **The Thirsty Plant** (`m-thirsty-plant`): new part: soil moisture probe on D33 (ADC1, powered from 3V3). New code
  idea: reading a probe and choosing a "too dry" number from real readings. If-line: `if soil.read() > DRY:` → LED on D25,
  else off. Swap the part: none. Challenge: a pretend pump (a servo tips a cup). 3D scene: a garden bed. Library: 7 soil builds
  plus many "automatic plant watering" builds.
- [x] **Rain, Rain, Go Away** (`m-rain-roof`, needs `m-servo`): new part: raindrop sensor board on D34 (analog, ADC1,
  listening-only). New code idea: wet means a *smaller* number. If-line: `if rain.read() < WET:` → servo swings the roof
  over the washing, else back. Swap the part: water-level sensor. 3D scene: a washing line beside a house. Library: the
  channel's signature build (rain-retracting clothesline, 34K likes) and ≈10 rain builds.
- [x] **Who's at the Door?** (`m-door`): new part: IR obstacle sensor on D14 (`Pin.IN, Pin.PULL_UP`, reads 0 when
  something is close; its little knob sets the range). New code idea: an active-low sensor. If-line: `if eye.value() == 0:`
  → buzzer on D13 beeps, else silent. Swap the part: PIR motion sensor, radar motion sensor (RCWL-0516), tilt switch on
  the door. 3D scene: a front door at night. Library: ≈41 IR builds (door and gate alarms, touchless taps). Replaces the
  earlier "Catch My Sibling" (PIR) and "Is the Door Open?" (reed switch) ideas.
- [x] **Follow My Hand** (`m-joystick`, needs `m-servo`): new part: joystick X on D35 (ADC1). New code idea: turning a
  reading into an angle, `x * 180 // 4095`. If-line: `if x < MIDDLE:` → servo left, else right (then the smooth version).
  Swap the part: a potentiometer. 3D scene: a crane arm on the desk. Library: "Joystick-Controlled Servo (KY-023)", ≈6
  joystick builds (goalkeeper games).
- [ ] **Too Hot in Here** (`m-too-hot`): new part: DHT11 on D4. New code idea: `import dht`, `measure()`,
  `temperature()`. If-line: `if t > HOT:` → red LED on D25, else green on D27. Replaces the landing page's smoke-alarm card
  as a heat alarm (no flame or gas sensors). Swap the part: none. 3D scene: a kitchen.
- [ ] **Don't Touch the Fence** (`m-touch-fence`): new part: none! A foil "fence" on a wire to D32, read with
  `TouchPad(Pin(32))`. New code idea: the ESP32 can feel a touch by itself; smaller number = touched. If-line:
  `if fence.read() < TOUCHED:` → buzzer on D13. Swap the part: a coin or a piece of fruit as the touch plate. 3D scene: a
  vegetable garden with a fence. Library: "Field Protection" electric-fence alarm (2 builds, pretend fence only).
- [ ] **Radar Scanner** (`m-radar`, needs `m-parking-gate`): new part: none new, the HC-SR04P is mounted on the servo horn.
  New code idea: a `for angle in range(0, 181, 10):` sweep that remembers the closest reading. If-line:
  `if d < closest:` → remember this angle; at the end, point the servo at it and print a little Shell map. Swap the part:
  none. 3D scene: a ship's radar screen. Library: "Ultrasonic Radar Scanner" (servo sweep + radar display).
- [ ] **Landing page**: smoke-alarm card → heat alarm, goal-counter card → IR obstacle (not laser), link each project card
  to its module, update the kit checklist.
